创建博客技术分析

个人博客搭建技术对比与实现细则，包括静态生成、内容管理和长期维护方式。

W
WyiZhng2025 年 4 月 17 日 · 12 min read

博客的技术方案很多，但真正重要的不是框架名称，而是它能不能让你更愿意写、方便维护，并且长期稳定地运行。

为什么个人博客适合静态生成

对于以文章为主的个人网站，内容通常在发布后不会频繁变化。构建时把 Markdown 转换成 HTML，访问者拿到的就是完整页面，不需要等待服务器查询数据库。

这让部署和备份都变得简单：文章跟着代码一起保存，站点可以直接发布到 GitHub Pages，也不需要持续维护一台服务器。

KEY TAKEAWAY

静态不是一种视觉风格，而是一种发布方式。页面是否好看，仍然取决于排版、内容层级和细节设计。

Hexo、WordPress 与 Astro

Hexo 上手快、生态成熟；WordPress 有完整后台，更适合多人维护和复杂业务；Astro 则保留了静态站点的轻量，同时提供现代组件化开发体验。

方案内容方式部署成本适合场景
HexoMarkdown低快速建立博客
WordPress在线后台中多人和动态功能
AstroMarkdown / MDX低现代定制型博客

先建立内容结构，再处理视觉

文章、标签、归档和搜索属于内容架构；字体、颜色、留白和动效属于视觉层。把两层分开之后，重新设计就不会影响原来的文章数据。

project-structure.txtsrc/
├─ content/posts/     # Markdown 文章
├─ components/        # 页面组件
├─ pages/             # 路由入口
└─ styles/            # 视觉规范

最终选择

对这个博客而言，保留 Astro 是更合适的方案。接下来只需要重新定义首页、文章列表、阅读页和全局设计变量，不必重新迁移内容。

一个好博客不需要表现得像复杂产品。它只需要让内容容易找到，让阅读保持舒服，并且让作者愿意继续写下去。
